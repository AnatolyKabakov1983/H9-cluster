# Виджет на основном экране

H9 Cluster умеет выводить те же автомобильные показания, что и приборная
панель на `Display ID 2`, в виджет на **основном экране** головного устройства.
Виджет добавляется в лаунчер штатным способом и обновляется раз в секунду.

## Размеры

| Виджет | Сетка | Состав |
| --- | --- | --- |
| `H9 Cluster · 4×2` | 4×2 | скорость, передача, обороты, топливо (литры, процент, шкала), запас хода, ОЖ, АКПП, напряжение |
| `H9 Cluster · 4×4` | 4×4 | всё из компактного плюс режим движения, наружная температура, мгновенный и средний расход, одометр, поездка, сутки, давление четырёх шин, напряжение, момент маховика, угол руля, скорости колёс |

Оба виджета можно размещать одновременно, в том числе в нескольких экземплярах.

## Как добавить

1. На основном экране откройте меню лаунчера «Виджеты» / долгое нажатие
   на свободном месте.
2. Найдите `H9 Cluster · 4×2` или `H9 Cluster · 4×4`.
3. Перетащите виджет на рабочий стол. Данные появятся в течение секунды.

Нажатие на виджет открывает экран настроек приложения.

## Как это работает

- Данные читают те же read-only источники, что и приборную панель:
  штатный `GwmAdapterService` (Binder), FDBus-подписка на RPM и счётчик
  топлива ECM2, снимок TBOX для температуры АКПП. Команды автомобилю не
  отправляются.
- Пока существует хотя бы один виджет, работает foreground-сервис
  `ClusterWidgetService` с постоянным уведомлением минимальной важности.
  Он хранит последний `ClusterState` и раз в секунду обновляет RemoteViews
  всех привязанных виджетов.
- Когда последний виджет удаляют, сервис останавливается и чтение
  автомобильных данных прекращается полностью.
- После перезагрузки головного устройства `BootReceiver` восстанавливает
  работу сервиса, если виджеты остались на столе.
- При переустановке приложения или перезапуске лаунчера виджеты перерисуются
  сразу из сохранённого снимка, не дожидаясь следующего такта.
- В Demo-сборке виджет питается синтетической поездкой
  (`DemoClusterDataSource`) и никогда не обращается к GWM Adapter, FDBus
  и TBOX.

## Согласованность с приборной панелью

- Виджет учитывает общий **режим показаний спидометра** (реальная скорость,
  `+4,5%` или `+5 км/ч`) — число совпадает с цифровым показанием темы.
- Виджет учитывает общий **объём бака**: литры и процент пересчитываются так
  же, как шкалы топлива во всех темах. Штатный запас хода продолжает
  приходить от автомобиля.
- Передача формируется по правилам `GearSelector`: `P`, `R`, `N`, `D3`, `M2`;
  без данных — прочерк.
- Температура АКПП устаревает через 15 секунд и показывается как `— °C`;
  цвет значения повторяет пороги карточки `ATF` (белый / жёлтый / оранжевый /
  красный).
- Мгновенный расход использует общий форматтер тем: `L/ч` на месте и
  `L/100` в движении; недоступные значения выводятся прочерком `—`.
- При недоступной измеренной скорости виджет показывает `0` только при свежем
  сочетании TBOX `engine running + Park` — та же защитная подстановка, что и
  в темах.

## Ограничения

- Виджет работает только если лаунчер поддерживает стандартные AppWidget.
  Штатные лаунчеры на Android 9 обычно поддерживают; если меню «Виджеты»
  отсутствует, используйте приборную панель на `Display ID 2` как раньше.
- Частота обновления RemoteViews — один такт в секунду. Это осознанный
  компромисс: виджет является средством наблюдения, а не заменой стрелочных
  приборов.
- Виджет не показывает штатные предупреждения QNX — для этого служит
  прозрачное окно на `Display ID 2`.

## Отладка

```bash
adb logcat -s GwmClusterDataSource ClusterWidgetService
adb logcat -s H9Diagnostics
```

В журнале сервиса ожидается последовательность: `service_created`,
`source_started`, затем такты обновления виджетов без ошибок.
