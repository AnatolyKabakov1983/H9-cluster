# Автомобильные показания на основном экране

H9 Cluster умеет выводить те же автомобильные показания, что и приборная
панель на `Display ID 2`, на **основной экран** головного устройства.
Данных два способа: плавающая панель (для головного устройства) и
стандартные виджеты (для телефона и лаунчеров с поддержкой AppWidget).

## Почему обычный виджет не виден на головном устройстве

Штатный лаунчер GWM на главном экране использует так называемые
**смарт-виджеты** — заводские карточки (климат, подогревы, навигация,
музыка), которые формируются системными приложениями GWM. Публичного
способа добавить в них свою карточку у стороннего приложения нет: меню
«Виджеты» стандартного Android в лаунчере нет, а список смарт-виджетов
ограничен заводскими. Поэтому AppWidget, который отлично работает на
телефоне, головное устройство просто не показывает.

Решение — **плавающая панель**: то же содержимое, что у полного виджета,
рисуется поверх главного экрана через `SYSTEM_ALERT_WINDOW`. Лаунчер для
этого не нужен, панель работает поверх любого экрана, включая страницу
смарт-виджетов.

## Плавающая панель на головном устройстве

1. Откройте приложение H9 Cluster (иконка на головном устройстве).
2. Нажмите кнопку **«Показать панель»** в нижнем ряду экрана настроек.
3. При первом запуске Android попросит разрешение «поверх других окон» —
   выдайте его, либо выполните команду с компьютера:

   ```bash
   adb shell appops set net.adminrunet.h9cluster SYSTEM_ALERT_WINDOW allow
   ```

4. Панель появится на главном экране поверх штатного интерфейса. Её можно
   **перетащить** в удобное место — позиция сохраняется.
5. Скрыть панель можно кнопкой «Скрыть панель» или действием
   «Скрыть панель» в постоянном уведомлении сервиса.
6. После перезагрузки головного устройства панель восстанавливается сама,
   если она была на экране.

Панель показывает полный состав данных, как виджет 4×4, обновляется раз в
секунду и питается тем же foreground-сервисом, что и виджеты.

## Стандартные виджеты (телефон и другие лаунчеры)

| Виджет | Сетка | Состав |
| --- | --- | --- |
| `H9 Cluster · 4×2` | 4×2 | скорость, передача, обороты, топливо (литры, процент, шкала), запас хода, ОЖ, заряд АКБ, напряжение |
| `H9 Cluster · 4×4` | 4×4 | всё из компактного плюс режим движения, наружная температура, мгновенный и средний расход, одометр, поездка, сутки, давление четырёх шин, напряжение, момент маховика, угол руля, скорости колёс |

Виджет добавляется в лаунчер штатным способом (долгое нажатие на свободном
месте → «Виджеты») и обновляется раз в секунду. Нажатие на виджет открывает
экран настроек приложения. На головном устройстве, где меню виджетов
отсутствует, используйте плавающую панель.

## Как это работает

- Данные читают те же read-only источники, что и приборную панель:
  штатный `GwmAdapterService` (Binder), FDBus-подписка на RPM и счётчик
  топлива ECM2, снимок TBOX. Команды автомобилю не отправляются.
- Пока существует хотя бы один виджет или открыта панель, работает
  foreground-сервис `ClusterWidgetService` с постоянным уведомлением
  минимальной важности. Он хранит последний `ClusterState` и раз в секунду
  обновляет RemoteViews всех привязанных виджетов и содержимое панели.
- Когда последний виджет удалён и панель скрыта, сервис останавливается и
  чтение автомобильных данных прекращается полностью.
- После перезагрузки `BootReceiver` восстанавливает сервис и панель.
- При переустановке приложения или перезапуске лаунчера виджеты
  перерисовываются сразу из сохранённого снимка, не дожидаясь следующего
  такта.
- В Demo-сборке виджет и панель питаются синтетической поездкой
  (`DemoClusterDataSource`) и никогда не обращаются к GWM Adapter, FDBus
  и TBOX.

## Согласованность с приборной панелью

- Виджет и панель учитывают общий **режим показаний спидометра** (реальная
  скорость, `+4,5%` или `+5 км/ч`) — число совпадает с цифровым показанием
  темы.
- Учитывается общий **объём бака**: литры и процент пересчитываются так же,
  как шкалы топлива во всех темах. Штатный запас хода продолжает приходить
  от автомобиля.
- Передача формируется по правилам `GearSelector`: `P`, `R`, `N`, `D3`, `M2`;
  без данных — прочерк.
- **Заряд АКБ** берётся из системной службы батареи головного устройства
  (`BatteryManager`); если платформа не отдаёт уровень, показывается
  прочерк. При заряде 20 % и ниже значение подсвечивается красным.
  Напряжение бортсети по-прежнему приходит от автомобиля
  (`car.basic.battery_voltage`).
- Мгновенный расход использует общий форматтер тем: `L/ч` на месте и
  `L/100` в движении; недоступные значения выводятся прочерком `—`.
- При недоступной измеренной скорости показывается `0` только при свежем
  сочетании TBOX `engine running + Park` — та же защитная подстановка, что
  и в темах.

## Ограничения

- Стандартные виджеты работают только в лаунчерах с поддержкой AppWidget;
  штатный лаунчер GWM их не показывает — на головном устройстве используйте
  плавающую панель.
- Для панели требуется разрешение «поверх других окон»
  (`SYSTEM_ALERT_WINDOW`).
- Частота обновления — один такт в секунду. Это осознанный компромисс:
  панель и виджет являются средством наблюдения, а не заменой стрелочных
  приборов.
- Панель и виджет не показывают штатные предупреждения QNX — для этого
  служит прозрачное окно на `Display ID 2`.

## Отладка

```bash
adb logcat -s GwmClusterDataSource ClusterWidgetService
adb logcat -s H9Diagnostics
```

В журнале сервиса ожидается последовательность: `service_created`,
`source_started`, затем такты обновления без ошибок. Для панели полезны
события `cluster_panel shown/hidden`.
